# Go machine CLI and shared base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bash `machine` CLI with Go, and have the front door call the same primitives in-process as an unprivileged user without sudo.

**Architecture:** One Go module at the repo root. `internal/machines` holds the config, names, status types and a `Manager` whose methods are the machine operations, running external tools through a `Runner`. `cmd/machine` and `cmd/front-door` are thin layers over it. The host module grants the front door's user exactly what `Create`, `Status` and `Login` need.

**Tech Stack:** Go 1.27 (`buildGo127Module`), tailscale.com v1.104.0 (front door only), NixOS module, NixOS tests.

**Spec:** `docs/superpowers/specs/2026-10-04-go-cli-design.md`

## Global Constraints

- Module path `github.com/devusb/flox-machines`, `go.mod` at the repo root, `go 1.27.1`.
- Binaries: `machine` and `flox-machines-front-door`, both from `pkgs/flox-machines.nix`, exposed as `packages.x86_64-linux.flox-machines`.
- `machine` output and errors match the bash CLI byte for byte: success lines `created machine-<name>` and `destroyed machine-<name>`, errors `machine: <message>` on stderr with exit 1.
- Config at `/etc/flox-machines/config.json`, overridden by `MACHINE_CONFIG`.
- Fixed reserved names: `admin root nobody sshd tailscale microvm nixbld`, plus `reservedNames` from config.
- Name pattern `^[a-z][a-z0-9-]{0,30}$`. Names of existing users with UID below 1000 are reserved.
- Front door user `flox-machines-front-door`, supplementary group `kvm`, no sudo.
- Unit tests run without root: `CGO_ENABLED=0 nix shell nixpkgs#go --command go test ./...`.
- NixOS tests build with `nix build -L --no-link --eval-store auto --store ssh-ng://mhelton@chopper .#checks.x86_64-linux.<name>`.
- Comments: none unless surrounding code has them; plain statements only.

## Review Focus

1. **Front door reading dnsmasq leases.** `Status` resolves the guest's IP from `/var/lib/dnsmasq/dnsmasq.leases`. The front door user must be able to read it, or every page stays "booting". Task 5's test asserts the page reaches the `login` state.
2. **`microvm -c` under the front door's sandbox.** The spike ran without `ProtectSystem=strict`. Any path `microvm -c` writes outside `ReadWritePaths` fails. Task 5's test creates through the page with the sandboxed unit.
3. **Owner file read by the front door.** A machine created by root's CLI with `--owner` must still be readable by the front door. Task 3 sets mode 0640, group `kvm`, and its test asserts the mode.
4. **Status JSON for a missing machine.** It must be exactly `{"name":"x","exists":false}`. Task 2's test asserts the bytes.
5. **Partial create left behind.** After a failed step, a later `machine create` of the same name must not be blocked by a leftover directory, unless a zvol had to be left. Task 3 tests both paths.

### Task 3: `Manager` primitives

**Files:**
- Create: `internal/machines/manager.go`, `create.go`, `ops.go`, `ssh.go`
- Create: `internal/machines/fake_test.go` (fake runner), `manager_test.go`, `create_test.go`

**Interfaces:**
- Consumes: Task 2's `Config`, `Runner`, `Status`, `ParseTailscaleStatus`, `ValidName`.
- Produces:
  - `type Manager struct { Config Config; Runner Runner; LookupUID func(name string) (uid int, ok bool) }`, `func NewManager(c Config) *Manager` with `ExecRunner` and `os/user` lookup.
  - `func (m *Manager) CheckName(name string) error`: `ValidName`, then `reserved name '<name>'` for fixed list, config list, or UID < 1000.
  - `Create(ctx, name, owner string) error`, `Status(ctx, name string) (Status, error)`, `Login(ctx, name string) error`, `Restart(ctx, name string) error`, `Resize(ctx, name string, memMB, vcpu int) error`, `ResizeReset(ctx, name string) error`, `Reimage(ctx, name string) error`, `Destroy(ctx, name string) error`, `List(ctx context.Context) (string, error)`, `GC(ctx context.Context) error`, `SSHArgs(name string, command []string) ([]string, error)`.
  - Error texts match the bash CLI: `no machine '<n>'`, `machine '<n>' exists`, `admin key <key>.pub missing`, `machine '<n>' has no address yet`, `could not start a Tailscale login on machine '<n>'`, `could not destroy <dataset>`.

Behavior follows `pkgs/machine-cli.nix` function by function, with these differences:

| Area | Behavior |
|---|---|
| Lock | `Create` holds `syscall.Flock(LOCK_EX)` on `<StateDir>/.lock-<name>` for its whole run |
| zvol | `zfs create -s -o com.sun:auto-snapshot=true -V <PersistSize>M <ParentDataset>/<name>`. Sparse because delegated creation was only verified sparse. |
| mkfs | `mkfs.ext4 -q -E root_owner=0:0 -L persist /dev/zvol/<dataset>` |
| Ownership | When `os.Geteuid() == 0`: chown the zvol device and `chown -R microvm:kvm` the machine directory, as today. Otherwise skip. |
| Owner file | `<dir>/owner`, mode 0640, group `kvm`; when root, user `root` |
| Cleanup | If a step after `microvm -c` fails: try `zfs destroy` of a zvol it created; if that succeeds or there was none, remove the machine directory and both gcroots; if not, leave everything and add `run 'machine destroy <name>'` to the error |
| SSH | `ssh -i <KeyPath> -o BatchMode=yes -o ConnectTimeout=5 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o LogLevel=ERROR root@<ip> ...` with per-call context timeouts of 5 s (reachability), 10 s (status), 15 s (login). `SSHArgs` omits `ConnectTimeout`, as `cmd_ssh` does. |
| Address | `MICROVM_MAC_0` from `<dir>/instance.env`, case-insensitive match on lease field 2, last match's field 3 |
